Learn: How Digital Signatures Work

Written for students. Each idea builds on the one before it.

1. Hashing: a fingerprint for data

A hash function such as SHA-256 turns any file into a fixed-length string. The same file always gives the same hash. Change even one character and the hash changes completely. You cannot work backwards from a hash to the file.

Highlighted characters changed since your last keystroke. Add or delete one letter and almost every character changes. This runs only in your browser.

2. Public-key cryptography: two linked keys

A key pair has a private key (secret) and a public key (shareable). Something signed with the private key can be checked with the public key, but the public key cannot be used to sign. Our project uses RSA with 2048-bit keys.

3. Signing and verifying

Document→ SHA-256 hash→ Sign with private key→ Signature

The receiver re-hashes the document and uses the signer's public key to check the signature. If both agree, the document is unchanged (integrity) and was signed by the key holder (authenticity). The signer also cannot easily deny signing (non-repudiation).

4. Digital signature vs similar terms

TermWhat it is
Digital signatureCryptographic proof of integrity and authenticity, built on hashing and a key pair.
Electronic signatureAny electronic sign of intent, such as a drawn signature or a ticked box. Not necessarily cryptographic.
EncryptionKeeps content secret. A signature does not hide the document; it proves it is genuine.
Digital certificateA document from a trusted authority linking a public key to a real identity.

5. Where digital signatures are used

  • Software updates and app stores (proving code was not altered).
  • HTTPS certificates on websites.
  • Signed PDFs, contracts and government e-documents.
  • Email signing (S/MIME, PGP) and code signing.

6. Threats and limits

  • Stolen private key: an attacker can sign as you. Protect it with a passphrase.
  • Wrong public key: a signature only proves "this key signed it". Real systems use certificates to tie a key to a person.
  • Tampering: any change to the document makes verification fail (try the sample below).
  • Weak algorithms: old hashes like MD5 or SHA-1 are broken. We use SHA-256.

7. Try the 6-step demo yourself

  1. Go to Keys and create a key pair. Download both PEM files.
  2. Download the sample document: sample_document.txt.
  3. On Sign, sign it and download the .sig.json file.
  4. On Verify, upload the same document and signature and choose your key. Result: VALID.
  5. Now verify using the tampered file: sample_document_tampered.txt (only the price changed from Rs. 500 to Rs. 5000). Result: INVALID, with "Document integrity" failing.
  6. Optional: create a second key pair and verify with the wrong public key. The "Signer key match" check fails.
